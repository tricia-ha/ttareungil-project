# 홍익대→집 경로 탐색 실험과 개선

실험일: 2026-11-02. 개인 주소와 인증키는 이 문서에 포함하지 않았습니다.

추가로 도보·따릉이·버스·지하철을 모두 사용하는 탐색을 여섯 출발·도착지에서 반복 비교했습니다. [최종 통합 비교 결과](INTEGRATED_BENCHMARK_20261103.md)를 참고하세요.

## 첫 경로를 확보하는 방법 비교

홍익대→집의 한 시각을 고정하고, 이미 확인된 도보와 시간표만 사용하는 초기 탐색 단계를 비교했습니다. 이 표는 통합 탐색 전체 성능이 아니라 기본 대중교통 경로를 확보하는 단계의 결과입니다. 각 방법을 순서와 역순으로 한 번씩 실행했습니다. 실제 이동시간의 정답을 검증한 실험은 아닙니다.

| 방법 | 함수 전체 평균 | 확보된 최단 예상시간 |
|---|---:|---:|
| 시간 확장 Dijkstra | 18.62초 | 상태 한도 내 미확보 |
| 확인된 그래프의 A* | 9.34초 | 71.51분 |
| 기존 시간표 순차 탐색 | 3.74초 | 71.51분 |
| 도달하지 않은 지점 처리 생략 | 2.60초 | 71.51분 |
| 도달 여부 재사용 + 일괄 정렬 | 1.99초 | 71.51분 |

Dijkstra는 전체 탐색 불가능을 의미하는 것이 아니라 이 실험의 10만 상태 제한에서 경로를 확보하지 못했습니다. A*는 확인된 연결로 구성한 정적 하한을 사용할 수 있는 단계입니다. 미확인 도보와 시간별 AI 예측이 포함된 통합 그래프에 이 속도를 그대로 기대할 수는 없습니다.

실제 최초 실행에서는 초기 시간표 탐색이 2초에 중단돼 약 79.83분 경로를 먼저 확보했습니다. 같은 초기 확인 연결로 충분히 탐색하면 71.51분이 가능했습니다. 기본 경로를 찾는 단계의 시간 부족과 본 탐색의 상태 증가가 함께 작용했습니다.

## 적용한 구조

1. 시간표를 출발시각 순으로 처리해 확인된 도보로 완성할 수 있는 기본 경로를 먼저 확보합니다. 아직 도달하지 않은 지점의 불필요한 처리를 건너뛰되, 하차할 수 없는 정류장을 통과하는 차량의 연결은 유지합니다.
2. 통합 탐색에서는 기존 도보·따릉이·버스·지하철 후보를 유지합니다. 주변 후보의 순서를 정할 때는 캐시만 확인하고, 실제 선택된 후보의 도보 계산을 진행합니다. 호출 한도 이후에도 계산 가능한 오프라인 도보는 계속 사용합니다.
3. 초기 시간표 탐색에는 전체 제한 안에서 2~5초를 배정합니다. 검색 중 확인된 도보가 생기면 마지막에 한 번 더 시간표를 비교합니다. 이미 경로가 있다는 이유로 더 빠른 조합을 확인하지 못하던 조건을 수정했습니다.
4. OSM 경로의 거리와 도로 유형을 읽는 계산은 묶어서 처리합니다. 경로·시간·특징 값과 합산 순서는 유지합니다.

대중교통만 남기거나 따릉이 사용 횟수를 한 번으로 제한하는 변경은 없습니다. 새 도보 호출 15~45회, 실제 탐색시간 30~150초, 일일 1,000회 한도와 P50·재고 모델·개인화 규칙은 유지합니다.

## 남은 한계

추가로 같은 고정 입력에서 상태 상한을 20만 개로 높이고 최대 150초를 허용했습니다. 이 단회 실험은 63.96초가 걸렸고, 10만 상태 실험과 같은 세 경로·예상시간을 반환했습니다. 새 API 호출은 0회였습니다. 이 사례에서는 계산량만 늘었으므로 상태 상한은 10만 개로 유지했습니다. 다른 OD까지 상한 확대가 무의미하다는 증거는 아닙니다.

- 실제 실행은 모두 10만 상태 한도에서 종료했으므로 전역 최적이나 완전한 k-최단경로를 보장하지 않습니다.
- 고정 입력 통합 비교는 같은 예측·기상 캐시를 재사용했습니다. 새 OD의 신경망 최초 추론 비용을 비교한 결과는 아닙니다. 실제 API 실행에서는 이동시간·재고 모델을 연결하고 새 추론도 수행했습니다.
- 모델·시간표·도로 준비시간은 여전히 첫 사용의 대기시간에 영향을 줍니다. 이번 성과를 전체 요청시간이 23% 감소한 것으로 해석하면 안 됩니다.

원시 결과는 프로젝트의 외부 실행 폴더 `<project>_local/outputs/runtime/diagnostics/search_upgrade_20261102/`에 보관했습니다. `paired_production.json`, `known_algorithms.json`, `full_algorithms.json`, `other_transit_pairs.json`, `walking_vectors.json`, `live_summary.json`, `validation_current/live_summary.json`을 사용했습니다.

상태 상한 비교는 `high_state_limit.json`에 별도로 보관했습니다. 기존 기본값을 기대하던 세 검사는 새 150초·45회 최대값과 자동 설정 활성화 여부를 확인하도록 갱신했습니다. 근접한 두 지점이 같은 보행 노드에 연결되는 예외도 검사해 빈 경로 구간의 배열 처리 오류를 수정했습니다. 화면의 취소·진행 표시·대기시간 표시 검사와 프로젝트 정적 검사도 통과했습니다.
