# 도보 비교 반복 실험 · 2026-11-02

## 방법

서울 주변 완료 타일 내의 지하철↔버스·지하철↔따릉이·버스↔따릉이·버스↔버스에서 매회 각 5개씩, 20개를 선정했습니다. 각 종류는 직선거리 30~300m 2개, 300~600m 2개, 600~900m 1개입니다. 세 회차의 물리적 구간은 정·역방향을 포함해 겹치지 않습니다. 경로 성공 여부를 보고 표본을 교체하지 않았습니다.

난수 시드는 20261103이며 날짜를 뜻하지 않습니다. 최초 12개 비교 표본과도 겹치지 않게 했습니다. 카카오를 비교 기준으로 사용했으며 실제 보행시간의 정답으로 간주하지 않습니다.

큰 차이는 절대차 2분 이상 또는 절대차 1분 이상이면서 대칭 시간비율 1.5배 이상으로 정의했습니다. 이는 실험용 운영 기준이며 통계적 유의성 검정은 아닙니다.

큰 차도 중심선을 이용한 연결은 기존 보호 조건으로 계속 카카오 확인 대상으로 두었습니다. 1회차 뒤에는 근거가 부족해 추가 조건을 넣지 않았습니다. 2회차까지의 자료에서 방향 변화가 6회 이상인 조건은 8개 중 4개가 큰 차이였으므로 후보로 정했습니다. 이 조건을 고정한 3회차에서 기존 보호 조건이 놓친 큰 오차 1개를 추가로 확인 대상으로 분류했습니다.

해당 사례는 촬영소사거리·우성그린아파트 → 답십리2동한양아파트앞입니다. OSM 약 11.08분, 카카오 16.05분으로 약 4.97분 차이가 났습니다. 도보 선형에서 큰 방향 변화가 10회였으며 큰 차도 태그만으로는 확인 대상으로 분류되지 않았습니다.

이 관찰은 복잡한 도보가 오차의 원인임을 증명하지 않습니다. 카카오 확인 우선순위를 정하는 보수적 조건으로 사용합니다. 기존 OSM 캐시를 읽을 때도 현재 조건을 다시 적용하므로 과거 값이 조건 검사를 우회하지 않습니다.

## 호출량과 재현

실험 새 호출은 60회입니다. 실행 완료 당시 프로젝트 기록상 당일 누적 397회로 일일 한도 1,000회 중 603회가 남았습니다. 다른 기기의 사용량은 포함하지 않습니다.

```powershell
python scripts/walking_iterations.py --max-new-calls 60
```

회차·표본·각 호출 결과는 중간 저장합니다. 같은 시드와 도보망으로 재실행하면 기록을 재사용합니다. 일일 누적 900회에 도달하면 새 호출을 멈춰 서비스용 100회를 남깁니다. 보고서는 outputs/runtime/diagnostics/walking_iterations_20261103.json에 저장됩니다. Git에는 인증키·실행 DB를 포함하지 않습니다.

적용 정책은 data/walking/verification_policy.json이며 큰 차도 보호 조건과 추가 complex_walk 조건을 사용합니다.
