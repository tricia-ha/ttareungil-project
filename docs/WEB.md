# PC 서버와 휴대폰 접속

## 시작과 종료

처음에는 `설치.cmd`, `웹_설치.cmd`, `OCR_설치.cmd`로 환경을 준비하고 `.env`에 인증키를 입력합니다. 이후에는 `웹_실행.cmd`와 `외부접속_실행.cmd`만 실행합니다.

- PC 접속: http://127.0.0.1:8765
- 같은 네트워크: 서버 창에 표시된 PC의 LAN 주소. Windows 방화벽의 개인 네트워크 접근 허용이 필요할 수 있습니다.
- 다른 와이파이·모바일 데이터: 외부 접속 창에 표시되는 HTTPS 주소 또는 QR
- 종료: 두 창에서 Ctrl+C 또는 `웹_종료.cmd`. 종료 명령은 저장된 PID의 프로젝트 경로를 확인한 뒤 해당 프로세스만 중지합니다.

외부 접속은 ngrok 무료 고정 개발 주소를 사용합니다. 최초 한 번 아래 설정을 진행합니다.

1. [ngrok 무료 가입](https://dashboard.ngrok.com/signup) 후 로그인합니다.
2. [Authtokens](https://dashboard.ngrok.com/authtokens)에서 `Add Authtoken`으로 생성한 인증 문자열을 복사합니다. `cr_`로 시작하는 관리 ID와 API Keys는 사용하지 않습니다.
3. [Domains](https://dashboard.ngrok.com/domains)에서 계정에 배정된 개발 도메인을 확인합니다. 별도 도메인 구매는 필요하지 않습니다.
4. `ngrok_설정.cmd`를 실행하고 Authtoken, 고정 도메인을 순서대로 입력합니다. 토큰 입력은 화면에 표시되지 않습니다.
5. 기존 서버가 켜져 있으면 `웹_종료.cmd`로 종료하고 `웹_실행.cmd` → `외부접속_실행.cmd` 순서로 실행합니다.

설치된 ngrok이 있으면 먼저 사용합니다. 없으면 최초 외부 접속 실행 시 공식 배포본을 내려받고 Windows 배포 서명을 검증합니다. Windows가 실행을 차단하면 [공식 Windows 설치 안내](https://ngrok.com/download/windows)의 Microsoft Store로 ngrok을 설치하고 실행 창을 다시 엽니다. 보안 설정을 해제할 필요는 없습니다.

인증 정보는 프로젝트의 형제 폴더인 `<프로젝트 폴더명>_local/web_ngrok.json`에 저장되며 웹에서 제공하지 않습니다. 기존 인증키를 다시 입력할 필요는 없습니다. 고정 주소 설정을 변경하면 웹 서버도 재시작합니다.

주소와 QR은 실행 결과 폴더의 `runtime/web/접속주소.txt`, `접속QR.png`에 저장됩니다. 같은 도메인을 유지하면 재시작해도 같은 QR 파일을 재사용합니다. PC·웹 서버·외부 접속 창이 켜져 있을 때만 접속할 수 있습니다.

무료 요금제는 월 HTTP 요청 20,000회·전송량 1GB 제한이 있으며 첫 접속 시 ngrok 안내 화면에서 계속하기가 필요할 수 있습니다. API 요청·작업 상태 조회도 사용량에 포함됩니다. 사용량은 [ngrok 대시보드](https://dashboard.ngrok.com/usage)에서 확인합니다. [공식 무료 요금제 안내](https://ngrok.com/docs/pricing-limits/free-plan-limits)

## 화면 사용

처음 화면에서 통합 경로·대중교통·따릉이 중 탐색 방식을 선택합니다. 장소 이름을 입력해 검색 결과를 선택하거나 지도에서 위치를 지정한 뒤 경로를 찾습니다. 결과는 전체·통합·대중교통·따릉이 필터로 나누어 볼 수 있습니다. 대중교통·따릉이 필터에서는 전용 경로를 추가로 요청할 수 있으며, 기존 결과는 유지합니다. 필터를 바꾸는 것만으로 새 탐색을 실행하지는 않습니다.

휴대폰에서는 하단 패널을 끌거나 손잡이를 눌러 펼칩니다. 실제 확보한 도로·노선 형상을 표시하며, 지도 선이 없는 구간을 임의의 직선 경로로 만들어 표시하지 않습니다.

출발·도착 주변 후보는 직선거리로 먼저 찾고, 시간표의 이동·대기와 연결 정보를 이용해 유리한 양쪽 연결부터 조회합니다. 교통수단별 후보에 기회를 주고 중간 환승용 조회 예산을 남깁니다. 이 순위는 검증된 성공 확률이 아니므로 확률 임계값으로 후보를 삭제하지 않습니다. 명백한 막다른 후보 제외와 기존 경로 보존 처리는 유지합니다.

경로 선택 후 `선택한 경로로 출발`을 누르면 브라우저의 위치 권한으로 현재 위치와 남은 경로 거리를 표시합니다. 위치는 서버에 저장하지 않으며, 화면에 표시한 이동시간은 기존 예측·시간표 결과를 사용합니다. `종료`나 다른 경로 선택 시 위치 추적을 중지합니다. 주소에 `?sim=1`을 붙이면 실제 위치 권한 없이 경로를 따라 이동하는 화면을 시험할 수 있습니다.

탐색은 서버 대기열에서 처리합니다. 처리 상태를 표시하고 끝나면 경로·시간·환승·구간별 이동을 보여줍니다. `partial`이면 한도 안에서 확보한 결과이며 전체 후보의 최단 경로를 보장하지 않습니다.

개인화는 원하는 아이디·비밀번호로 가입 → 사진 선택 → 한 건 범위 조절 → OCR 결과 확인·수정 → 등록 순서입니다. 표시된 번호와 대여소 이름이 다르거나 목록에 없는 경우에는 등록을 보류합니다. 원본 사진을 서버 파일로 보관하지 않고 메모리에서 처리합니다. 확인된 기록·사진 해시·기본 P50·날씨·검증 결과는 개인 DB에 저장합니다.

사진 등록 화면에는 `내 기록으로`, `패널 접기`, 사진 미리보기 접기를 제공합니다. 돌아가도 선택한 사진과 수정 내용은 현재 페이지에 유지되며 `등록 계속하기`로 이어갈 수 있습니다. 페이지를 새로고침하면 등록 전 사진·수정 내용은 사라집니다. 실패 시 누락 항목과 재시도·자르기 조정·다른 사진 선택을 안내합니다. 인식 중 화면을 접어도 서버 작업은 계속됩니다.

이용내역 화면은 확인되지만 일부 글자를 읽지 못하면 `직접 입력·수정`으로 빈 항목을 입력할 수 있습니다. 번호·이름·대여/반납 시각·이용시간·거리·자전거 번호를 원본과 대조한 뒤 확인해야 합니다. 수정한 값에도 동일한 검증·과거 날씨 조회·기본 P50 계산·개인화 절차가 적용됩니다. 일반 사진처럼 이용내역의 근거를 확인할 수 없는 이미지는 직접 등록을 허용하지 않습니다.

개인화 화면에는 현재 보정에 사용한 기록 수, 배율·고정 시간 보정과 10분 구간의 예시를 표시합니다. 보정에서 제외된 기록은 저장 여부와 제외 이유를 구분하며, 경로 결과에는 따릉이 구간에 실제 개인화를 적용했는지 안내합니다. 개인화는 배율과 고정 시간 보정을 함께 추정합니다.

아이디는 한글·영문·숫자·밑줄·점·하이픈으로 2~32자, 비밀번호는 8~128자입니다. 아이디의 영문 대소문자는 구분하지 않습니다. 비밀번호는 개별 salt와 scrypt 해시로 저장합니다. 다른 기기에서도 같은 아이디·비밀번호로 로그인합니다. 자동 복구 기능은 없으므로 로그인 정보를 보관합니다. 로그아웃은 해당 기기의 연결만 해제하며, 계정 삭제는 모든 기기의 해당 기록을 삭제합니다.

공유 주소나 개인화 프로필 식별값만으로 로그인할 수 없습니다. 등록된 계정의 유효한 로그인 증명이 필요합니다. 같은 브라우저의 새 탭은 기존 로그인 상태를 공유합니다. 서로 다른 사람이 같은 PC를 쓰면 로그아웃하거나 브라우저 프로필을 구분합니다.

로그인 후 `비밀번호 변경`에서 현재 비밀번호를 확인하고 12~128자의 새 비밀번호로 변경할 수 있습니다. 이용기록과 개인화는 유지하고, 다른 기기의 기존 로그인은 무효화합니다. 다른 사이트와 같은 비밀번호는 사용하지 마세요. 비밀번호 변경 기능을 처음 적용할 때 기존 로그인은 한 번 해제되므로 다시 로그인합니다.

## 서버 동작

- FastAPI/Uvicorn 한 프로세스에서 경로 탐색을 최대 2건 동시에 처리합니다. 모델은 한 번만 로드하고 예측 계산은 공용 잠금으로 보호합니다.
- PC 자원이 부족하면 추가 탐색을 대기시킵니다. 두 번째 탐색은 여유 메모리 6GiB 이상·전체 CPU 사용률 85% 미만일 때 시작합니다. 최초 모델 준비 중에는 한 건씩 처리합니다. 메모리를 측정할 수 없는 환경도 한 건씩 처리합니다.
- 서버의 수치 계산 스레드는 2개로 제한하고 Windows에서는 서버 프로세스의 우선순위를 낮춥니다. OCR·사진 등록 확인은 경로 탐색과 겹치지 않게 처리합니다. 자원 부족으로 120초 동안 시작하지 못하면 재시도 안내를 표시합니다.
- 실행·대기를 합쳐 최대 6개, 브라우저별 진행 작업은 1개입니다. 경로 탐색 2건이 실행 중이면 최대 4건이 대기합니다. 대기시간·자료 준비시간은 경로 탐색 제한시간과 별도입니다.
- 같은 도보 구간의 동시 요청과 전체 재고 갱신은 중복 호출을 피하도록 공유합니다.
- 새 도보 API 호출은 작업당 기본 최대 20회, 로컬 일일 한도 1,000회
- 현재 재고는 연속 탐색 시 최소 60초 간격으로 새로 조회하고, 재고 판단 시각은 각 대여소에 도착할 시각 사용
- 장소 검색은 버튼을 눌렀을 때 조회하고 결과를 캐시. 정확한 대여소 번호·이름은 보유 목록에서 조회
- HTTPS의 HttpOnly 쿠키, 동일 출처 요청 확인, 브라우저별 작업 소유권 확인
- 웹 파일만 제공. 모델·DB·인증키·로컬 경로는 파일 다운로드로 노출하지 않음

키는 브라우저에 전달하지 않습니다. 사진 파일 경로를 네트워크 입력으로 받지 않고 이미지 바이트만 받습니다. 웹 개인화 DB는 `cache/runtime/web_personalization.sqlite`이며 기존 Python용 `personalization.sqlite`와 분리합니다. 웹에서는 새 ID로 시작합니다. `bicycle_local/cache`가 있으면 그 위치를 사용합니다.

## 설정과 주의점

`.env`의 `WEB_MAX_KAKAO_CALLS`로 작업당 도보 호출 상한을 설정할 수 있습니다(1~80). 일일 한도를 늘리지는 않습니다. ngrok은 설정한 도메인 하나만 자동 허용합니다. 별도 사용자 도메인은 `WEB_ALLOWED_HOSTS`에 호스트 이름을 쉼표로 나눠 입력하고 서버를 다시 실행합니다. PC LAN 주소도 허용하며 이전 터널 주소와의 호환 동작은 유지합니다.

PC를 절전 모드로 두거나 인터넷을 끊으면 접속·탐색이 중단됩니다. 첫 따릉이 탐색·OCR은 모델과 도로망 준비로 오래 걸릴 수 있습니다. 자료 누락·API 권한·호출 한도는 별도로 확인해야 합니다. 이 구성은 소규모 프로토타입·시연용이며 대규모 동시 접속 성능은 검증하지 않았습니다.

직접 함수 연결 방법은 USAGE.md, 이미지 검증과 개인화 원리는 SCREENSHOT_IMPORT.md와 PERSONALIZATION.md를 참고하세요.

## 탐색 중 결과 표시

완성된 경로는 탐색 종료 전에 먼저 표시하며 약 1초 간격으로 갱신합니다. 전체 이동시간이 짧은 경로가 항상 맨 위에 옵니다. 사용자가 선택한 경로·펼친 구간 설명은 가능한 한 유지하고, 남은 후보 탐색은 기본 30초까지 계속합니다. 화면 구성 시간은 순수 탐색시간과 별도입니다.

완성된 경로가 0개이면 탐색 종료 사유와 도보 조회 사용량을 표시합니다. 새 검색을 시작하거나 결과가 없을 때는 이전 경로의 지도 선을 지웁니다. 시간·조회 한도로 끝난 경우는 실제 이동 가능한 경로가 없다는 뜻이 아닙니다.

같은 대중교통 차량·승하차 지점과 따릉이 대여·반납 조합을 사용하는 경로는, 연속 도보의 출발·도착이 같으면 중간 도보 경유지만 달라도 하나로 묶습니다. 빠른 경로를 남기며 도착시간이 같으면 도보가 짧은 쪽을 선택합니다. 다른 환승역·정류장이나 따릉이 조합은 유지합니다.

같은 주소·브라우저에서 새로고침하면 진행 중인 탐색에 다시 연결하며 출발·도착지와 탐색 조건도 복원합니다. 접수 후 15분 이내의 완료 결과도 다시 표시합니다. 새 계산을 요청하지 않으므로 API를 추가 호출하지 않습니다. 서버 재시작이나 쿠키 삭제 후에는 기존 작업을 복원할 수 없습니다.
