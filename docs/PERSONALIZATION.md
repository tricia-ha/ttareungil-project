# P50 개인화

개인 ID가 없거나 이력이 없으면 기본 P50을 사용합니다. 기본식은 `개인 P50 = factor × 기본 P50 + offset_min`입니다. 배율과 분 단위 고정 보정을 함께 추정합니다. 고정 보정에는 대여·반납 행동뿐 아니라 모델 오차도 섞일 수 있습니다.

- Huber 방식으로 큰 잔차의 영향을 줄이고, 기록이 적거나 불안정하면 배율 1·고정 보정 0에 가깝게 정규화합니다. 기존 정책의 prior_strength=10, instability_scale=0.3을 재사용하며 실제 개인 자료로 최적화한 값은 아닙니다.
- 관측한 기본시간이 비슷하면 배율을 구분할 정보가 부족합니다. 같은 기본시간만 반복되면 배율은 1로 유지하고 고정 시간 차이를 추정합니다.
- 배율은 기존 0.7~1.5 범위를 유지합니다. 최종 시간은 관측된 실제/기본 비율과 기존 정책으로 정한 양수 구간 안에서 제한하여 짧은 구간의 음수 예측을 방지합니다.
- 따릉이 P50만 보정하고, 변경된 도착시각으로 재고와 환승 가능성을 다시 확인합니다. 도보·버스·지하철 시간과 P80·P90은 바꾸지 않습니다.

신경망을 다시 학습하지 않습니다. 공통 기본 예측 캐시 뒤에 보정을 적용하므로 기존 캐시와 이력을 재사용합니다. 이력은 모델·기준 예측 버전별로 구분합니다. `scripts/evaluate_personal_affine.py`에서 이전 기록만으로 다음 기록을 예측해 기존 배율 방식과 비교합니다. 이 합성 실험은 실제 사용자 성능 검증이 아닙니다.

## 이상 이력

기본 정책은 개인의 과거 로그 비율에 대한 단측 95% Student-t 예측 상한입니다. 새 기록이 상한을 초과하면 개인화 갱신에서 제외하고 원기록과 판정 근거는 남깁니다. 입력한 기록보다 이전에 완료된 이력만 판정에 사용합니다.

참조 기록이 2건 미만이거나 분산을 계산할 수 없으면 자동 제외를 유보합니다. 원래 느린 이용자는 자신의 과거 수준과 비교합니다. 통계적으로 긴 기록을 판별하는 것이며 운동·레저 목적 자체를 확정하는 것은 아닙니다.

`.env`의 기본 설정은 `PERSONALIZATION_HISTORY_METHOD=student_t`, `PERSONALIZATION_HISTORY_ALPHA=0.05`, `PERSONALIZATION_HISTORY_MODE=active`입니다. 실제 사용자 자료에서 정상 기록 오제외율과 다음 이용 예측 성능은 추가 검증이 필요합니다.

## 연결

`create_profile()`로 ID를 발급하고 사진 등록을 완료한 뒤 `find_routes()`에 `profile_id`를 넣습니다. `get_profile()`은 배율 `factor`와 고정 보정 `offset_min`, `list_rides()`는 반영·제외 여부를 반환합니다. 이력을 삭제하면 남은 이력으로 두 값이 다시 계산됩니다. `legacy_factor`는 비교용 기존 배율이며 실제 보정에 쓰지 않습니다.

ID별 이력은 SQLite DB에 저장됩니다. 기본 경로는 `cache/runtime/personalization.sqlite`이며 기존 `bicycle_local/cache`가 있으면 그 위치를 사용합니다. 원본 사진은 저장하지 않습니다. ID와 DB는 개인 자료이므로 보관에 주의해야 합니다.
