# 시간표 수집

경로를 검색할 때 웹 시간표를 수집하지 않습니다. `시간표_수집.cmd` 또는 `03_시간표수집.ipynb`에서 별도로 수집·검증한 뒤 저장된 자료로 탐색합니다.

## 구분

- 평일 / 토요일 / 일요일·공휴일을 따로 저장합니다. 토요일과 일요일을 같은 시간표로 복제하지 않습니다.
- 평일이나 토요일이라도 법정공휴일이면 휴일 시간표를 선택합니다.
- 자정 이후 열차는 운행을 시작한 날짜에 연결합니다. 토요일 막차가 일요일 00시에 운행하더라도 토요일 표에 속합니다.
- 상·하행, 급행·일반, 지선, 출발·종착역과 열차번호를 분리합니다.
- 특정 역에 평일 표만 제공되면 주말 운행을 만들어 넣지 않습니다. 수집 응답에서 경춘선 광운대역은 평일 표만 확인되었습니다.
- 에버라인은 주말 응답에 열차번호가 없어 역 사이의 동일 열차를 검증할 수 없습니다. 평일만 연결하며 주말 운행을 추정해 넣지 않습니다.

## 수집과 이어받기

공개 지하철 시간표의 수도권 노선·역 목록과 역별 응답을 수집합니다. 요청은 하나씩, 기본 1.5초 간격으로 보냅니다. 성공한 역마다 저장하며 재실행하면 최근 7일 안에 저장된 응답을 재사용합니다. 인증 오류·접근 차단·429 응답이 오면 우회하거나 반복 요청하지 않고 중단합니다.

수집이 끝나기 전에는 기존 사용 시간표를 덮어쓰지 않습니다. 완료 후 노선·요일별 파일을 만들고 마지막에 사용 버전을 전환합니다. 응답 원본과 수집 진행표는 Git에서 제외하며, 검증된 시간표와 그 출처·버전만 프로젝트에 포함합니다.

저장 위치: `data/transit/map_timetables/`. `manifest.json`에 현재 버전·수집 범위·사용 노선이 기록됩니다. `compiled/`에는 노선별 평일·토요일·휴일 시간표가 있습니다.

```powershell
.venv\Scripts\python.exe -B scripts/collect_map_timetables.py --compile
```

`--max-requests 20`으로 한 번의 요청 수를 제한하거나 `--refresh`로 전체를 다시 수집할 수 있습니다. 기존 시간표로 검색만 할 때는 수집을 실행할 필요가 없습니다. 수집한 내용은 변경될 수 있으므로 서비스 사용 전 최신 여부를 확인합니다.

## 출처 선택과 남은 부분

2026-11-01 수집: 수도권 24개 노선의 역·호선 조합 799개입니다. 연결 가능한 수집 기록 624,147건에 도착시각 추정 4,303건을 더해, 열차별 역 방문 기록을 평일 241,260건·토요일 193,595건·휴일 193,595건으로 변환했습니다. 기존 운영사 자료를 유지하는 노선의 추정분은 탐색에 사용하지 않습니다. 23개 노선은 세 구분 모두 연결이 확인되었고 에버라인은 평일만 확인되었습니다. 토요일·휴일 응답이 같은 노선도 각각의 응답을 따로 저장했습니다.

출처는 [네이버 공개 지하철 시간표](https://pts.map.naver.com/end-subway/ends/web/133/home)입니다. 공식적으로 보장된 대량 수집 API가 아니므로 응답 형식이나 제공 범위는 바뀔 수 있습니다.

신분당선·우이신설선·신림선은 기존 분 단위 열차 연결 추정 대신 수집한 열차번호·도착·출발시각으로 연결합니다. 새로 확보한 노선도 같은 방식으로 추가합니다. 기존에 종착역 도착시각까지 있는 운영사 전체 열차표는 유지합니다.

지도 역별 시간표도 종착역에 들어오는 편은 빠지고 출발하는 편만 제공되는 경우가 있습니다. 공개되지 않은 도착시각을 임의로 만들거나 반대 방향 출발시각으로 대체하지 않습니다. 따라서 수집 완료가 모든 종착역 도착 구간의 복원을 뜻하지 않습니다.

여기서 종착역은 노선 끝 역뿐 아니라 해당 열차가 운행을 끝내는 중간역도 뜻합니다. 같은 노선·요일·방향·운행 유형에서 해당 한 구간의 관측 소요시간이 여러 열차에서 모두 같을 때만 마지막 출발시각에 그 값을 더합니다. 원래 열차번호·행선지는 유지하며, `ARRIVAL_INFERRED=1`과 별도 방법 이름으로 추정값을 구분합니다. 다른 열차의 기록을 해당 열차에 붙이거나 없는 중간 구간을 건너뛰지 않습니다. 값이 달라지거나 관측이 부족하면 보완하지 않습니다.

이 조건으로 실제 사용하는 새 시간표에서는 요일표를 합쳐 588편의 마지막 한 구간을 추가했습니다(경강선 24·김포골드라인 372·서해선 141·신분당선 8·인천1호선 43). 기존 관측 행의 시각은 바꾸지 않았습니다. 같은 구간을 달리는 열차의 자료를 이용한 추정이며, 해당 종착편의 실제 도착시각을 직접 확인한 결과는 아닙니다.

버스는 현재 첫차·막차·배차간격으로 운행을 복원하는 부분이 남습니다. 역별 지하철 시간표를 수집했다고 해서 버스의 실제 차량별 시각표까지 확보된 것은 아닙니다. TOPIS의 `1.HHMM` 익일 표기를 해석하지 못하던 문제는 별도로 수정했습니다.

## 기존 계산 방식의 보완 가능성 검사

실제 열차번호가 있는 신분당선·우이신설선·신림선과 에버라인의 자료에서 번호를 가리고 기존 분 단위 연결 알고리즘을 적용했습니다. 검사한 연결에서는 다른 열차끼리 연결한 사례가 없었으나, 출발시각 간 차이를 이동시간으로 사용해 실제 도착시각 기준과 평균 약 30~35초 차이가 있었습니다. 이는 수집한 자료 안에서의 확인이며 다른 운행표에 대한 보장은 아닙니다.

도착시각 보완은 위의 일정한 구간 소요시간이 확인되는 경우로 제한했습니다. 에버라인 주말은 대조할 열차번호가 없어 정확성을 검증하지 못했으므로 추정 연결을 사용하지 않습니다. 검사 결과는 `data/transit/map_timetables/fallback_validation.json`, 재현은 `python scripts/check_timetable_fallback.py`입니다. 이 검사의 정답에는 추정한 도착 행을 포함하지 않습니다.

## 버스 웹 시간표

`버스시간표_수집.cmd` 또는 `04_버스시간표수집.ipynb`에서 공개 HTML 표를 수집합니다. 검색 요청 중에는 크롤링하지 않습니다. 추가 API 키는 필요하지 않습니다.

2026-11-01에 [서울공항리무진](https://seoulairbus.co.kr/bus/6009)의 6006·6009·6020·6200·6300·6500·6600번과 [서울시 자율주행버스 안내](https://scpm.seoul.go.kr/seoul-policy/evt0196)의 동대문A01·서대문A01을 수집했습니다. 총 17회 요청했으며, 성공한 페이지는 7일간 재사용합니다. 403·429·표 형식 오류가 나면 중단하고 기존 정상 파일을 보존합니다.

- 공항버스: 같은 표 행에 게시된 시내 출발·공항 도착시각을 사용합니다. 반대 방향 열의 시각을 같은 차량으로 합치지 않습니다. 시내 정류장 사이 승하차 경로는 허용하지 않습니다. 시내 도착시각이 없는 공항발 방향은 만들지 않습니다.
- 동대문A01: 현재 노선의 정류장 23개와 게시 순서가 일치해 평일 출발 6편을 적용합니다. 게시된 전체 운행 구간의 시간과 중간 정류장별 실제 도착시각은 구별합니다. 중간 시각은 아래 운행 통계 또는 거리 비례로 추정합니다.
- 서대문A01: 게시된 10개와 현재 자료의 14개 정류장 순서가 달라 적용하지 않습니다.
- 요일: 별도 평일·휴일 표에 토요일의 적용 근거가 없으면 토요일 표를 복제하지 않습니다. 운영사가 공통 표 하나를 제공하는 경우만 공통 표로 기록합니다.

노선번호만 비슷하거나 이름이 비슷한 정류장을 추측해서 연결하지 않습니다. 정류장 ARS 번호와 현재 노선의 정류장 ID를 연결하며, 유일하게 확인되는 경우만 사용합니다. 수집 결과는 `data/transit/bus_web_timetables.json`에 저장됩니다. 일반 시내버스 전체의 실제 차량별 출발표를 확보한 상태는 아닙니다. 그 노선들은 기존 첫차·막차·배차간격 출발 추정을 유지합니다.

## 버스 정류장 사이 이동시간 보완

[서울시 시간대별 버스 구간 운행 자료](https://data.seoul.go.kr/dataList/OA-21217/S/1/datasetView.do)의 2026-10-12~18 자료 575,088행을 확인했습니다. 현재 노선 ID·출발/도착 정류장 ID·순서가 일치하는 545,780행에서 81,094개 방향 구간의 요일·시간대별 대표값을 만들었습니다. 운행시간은 초 단위로 처리합니다. 이는 실제 출발 시간표가 아닌 과거 구간 운행 통계입니다.

하루별 시간대 평균값들을 요일 구분별로 모아 중앙값을 사용합니다. 0은 결측이며, 구간이나 시간대가 없으면 기존 거리 비례 시간을 유지합니다. 자정을 지나면 실제 통과일의 요일과 시간대를 사용합니다. 공항버스에 게시된 정류장별 시각은 이 통계로 덮어쓰지 않습니다.

가공본 `data/transit/bus_section_times.json.gz`는 약 6.6 MiB이며 프로젝트에 포함됩니다. 원본 ZIP은 별도 보관합니다. 새 원본을 받은 경우에만 다음을 실행합니다.

```powershell
.venv\Scripts\python.exe -B scripts/prepare_bus_section_times.py "원본 ZIP 경로"
```

월~목 4일로 통계를 만들고 금요일을 남겨 비교한 결과, 418,307개 구간·시간대 관측값의 평균 절대오차는 기존 거리 비례 37.18초, 통계 보완 14.99초였습니다. 통계가 없는 575개에도 기존 값을 유지한 전체 비교입니다. 실제 승객의 전체 이동시간이나 버스 도착 예측 정확도 측정은 아니며, 1주 자료로 주말 일반화까지 검증한 것은 아닙니다.

## 지하철 진입·환승과 연결 범위

[서울교통공사 환승거리·소요시간](https://data.seoul.go.kr/dataList/OA-13290/F/1/datasetView.do)의 방향별 값을 적용합니다. 일반 보행속도로 환산한 값이며 개인별 실측값은 아닙니다. 자료가 없는 동일 역 환승에는 기존 추정시간을 유지합니다. 거리만 가까운 다른 역을 같은 환승역으로 합치지 않습니다.

역에 처음 들어갈 때는 기존 2분을 유지합니다. 열차에서 내린 뒤 내부 환승 보행을 마쳤으면 2분을 다시 더하지 않습니다. 다른 역에서 내려 외부 도보로 새 역에 들어가면 진입 여유시간을 적용합니다.

기존 900m 후보와 접근 보행 30분·80m/분으로 계산한 2.4km 보조 범위는 삭제하지 않습니다. 대신 OD 길이와 출발·도착 주변의 정류장·역·대여소 개수를 따로 계산해 양쪽의 우선 탐색 반경을 각각 정합니다. 교통수단이 밀집한 곳은 가까운 후보를 먼저 확인하고, 희소한 곳과 긴 OD는 반경을 먼저 넓힙니다. 우선 반경 밖 후보도 제거하지 않고 가까운 후보 2건당 보조 범위 1건을 교차 확인해 장거리 도보 연결을 유지합니다. 실제 도보시간은 지도 응답, 따릉이 시간은 모델로 계산합니다. `adaptive_connections=False`는 고정 900m 비교용입니다. 웹 탐색은 준비시간을 제외한 실제 탐색을 후보 규모에 따라 30~150초로 제한하고 후보 소진·최적성·구조적 한도 확정 시 먼저 종료합니다. 새 도보 조회 한도도 15~45회/검색으로 자동 설정하며 일일 1,000회는 유지합니다.
